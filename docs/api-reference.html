API Reference

Full interactive docs (auto-generated from the Pydantic schemas) live at /docs on a running instance. This page is the map — what's where, and how auth works.

Two API surfaces

PrefixAudienceAuth
/api/*Staff appStaff JWT, permission-gated per endpoint
/api/public/*Customer siteCustomer JWT (optional on most endpoints — guest checkout/reservations work without an account) or fully anonymous

Authentication

Two independent JWT systems sharing one secret key, disambiguated by a type claim ("staff" or "customer") so a staff token can never be used against customer endpoints or vice versa. Both tokens also carry a business_id claim — this is how an authenticated request gets tenant-scoped without needing any header (see Multi-Tenancy).

Anonymous endpoints require tenant context

Every public endpoint reachable without authentication depends on require_tenant — it 400s if business_id couldn't be resolved, rather than silently running an unscoped query. See Multi-Tenancy for why this exists.

Conventions worth knowing

  • Server-side pricing, always. Checkout, refunds, and discount calculations never trust a client-sent amount — every price is recomputed from the product/order record.
  • Permission dependencies are declared per-route (Depends(require_permission("orders.refund"))), not inferred — see Roles & Permissions.
  • List endpoints cap their limit parameter (typically le=500) — see Security & Hardening.
  • Audit logging — every mutating staff endpoint calls a shared log_action(), recorded in AuditLog.
