Deployment

Everything so far has run locally via Docker Compose. This page covers what changes to run it somewhere real.

Not yet exercised

Nothing has actually been deployed outside a local machine yet. The recommendation below is a considered plan, not a battle-tested path — the jump from docker compose up to a real host usually surfaces at least one surprise.

Recommended path — no credit card required

Render (web service, from the existing backend/Dockerfile) + Neon (managed Postgres) both have genuine no-card-required free tiers. Since the backend serves the frontend itself, one Render service covers everything — no separate static site host needed.

Environment variables to set

VariableNotes
DATABASE_URLNeon's connection string, with the SQLAlchemy driver suffix (postgresql+psycopg2://...) and ?sslmode=require appended
SECRET_KEYGenerate a real random secret — don't ship the default dev value
STRIPE_SECRET_KEYLive key when ready for real payments; test key otherwise
STRIPE_WEBHOOK_SECRETFrom a webhook endpoint registered in the Stripe Dashboard pointing at /api/public/webhooks/stripe
STRIPE_CONNECT_WEBHOOK_SECRETFrom a separate webhook registered with "Listen to: Events on connected accounts," pointing at /api/public/webhooks/stripe-connect — see Payments
STRIPE_SUBSCRIPTION_PRICE_IDThe subscription Product/Price from the Stripe Dashboard
RESEND_API_KEY, RESEND_FROM_EMAILFor real transactional email — degrades gracefully (logs only) if unset
PUBLIC_SITE_URLThe real public URL, used to build Stripe redirect URLs correctly

Start command

Must bind to Render's $PORT, not the hardcoded 8000 in the Dockerfile:

sh -c "alembic upgrade head && python -m app.seed && uvicorn app.main:app --host 0.0.0.0 --port $PORT"

Do the migration work before pointing this at real data

Render's free web service is disposable/ephemeral by nature, but Neon's database is not. Hand-patching schema changes against a live production database is not a sustainable practice — get comfortable with the Alembic workflow (see Getting Started) before real tenants' data depends on it.

Render's free tier spins the service down after 15 minutes of inactivity (~1 minute cold start on the next request) — fine for a small shop's actual traffic pattern, not for something needing instant always-on access.

Backups

See Security & Hardening for the manual backup_db.sh/restore_db.sh scripts. Once on a real managed Postgres host, prefer its built-in automated backups over relying solely on the manual scripts — Neon includes this on its free tier.

Stripe webhooks in production

Local development uses stripe listen to forward events to localhost. In production, register two real webhook endpoints in the Stripe Dashboard against the public URL — one normal, one explicitly scoped to Connect events — matching the two endpoints described in Payments.
