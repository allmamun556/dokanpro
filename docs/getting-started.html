Getting Started

Everything runs from two Docker Compose services. One command starts the whole system.

Run it

cd pos-system
docker compose up -d

The backend container's startup command runs Alembic migrations, seeds demo data (idempotent — safe to run every time), and starts Uvicorn, all automatically:

sh -c "alembic upgrade head && python -m app.seed && uvicorn app.main:app --host 0.0.0.0 --port 8000"

Check it's healthy

docker compose ps
docker compose logs backend --tail 20

Key URLs

Staff apphttp://localhost:8000/t/{slug}/
Customer ordering sitehttp://localhost:8000/t/{slug}/site/
New restaurant signuphttp://localhost:8000/signup.html
API docs (Swagger)http://localhost:8000/docs
Health checkhttp://localhost:8000/api/health

Every URL for a specific tenant is prefixed with /t/{slug}/ — see Multi-Tenancy for why. The bare / and /site/ paths still render but can't log in (no tenant context to resolve).

Creating another tenant

Two ways to create a new business on the same deployment:

  • Self-serve signup — /signup.html, the real product flow a restaurant owner would use.
  • Management script — for quick local testing without going through the UI: 
    docker compose exec backend python -m app.create_tenant "Test Cafe" "test-cafe"
    Defaults to admin@{slug}.example.com / changeme123 if you don't pass an email/password.

Making code changes

Frontend files (frontend/) are bind-mounted — edits are live immediately, no rebuild needed.

Backend files are baked into the image at build time — after any Python change:

docker compose build backend && docker compose up -d backend

Generating a migration

Must be run via a bind-mounted container, or the generated file is lost when the ephemeral container exits:

docker compose run --rm --user "$(id -u):$(id -g)" \
  -v "$(pwd)/backend:/app" backend \
  alembic revision --autogenerate -m "description"

Rebuild the image after the migration file exists, never before — the Dockerfile does COPY . . at build time, so a build before generation bakes in an empty alembic/versions/.

Stopping

docker compose down        # keeps data
docker compose down -v     # also wipes the database volume
See Deployment for running this somewhere other than your laptop.
